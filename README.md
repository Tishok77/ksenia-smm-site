# Ксения — сайт-визитка SMM-специалиста

Одностраничный адаптивный сайт-портфолио. React + Vite, чистый CSS,
без бэкенда — статическая сборка, которая размещается на GitHub Pages.

## Стек

- React 19 + Vite
- Обычный CSS (переменные для палитры/типографики, без препроцессоров и UI-фреймворков)
- Self-hosted шрифты через `@fontsource` (Manrope + Cormorant Garamond Italic)
- Анимации — на CSS + `IntersectionObserver`/`requestAnimationFrame` без сторонних анимационных библиотек

## Установка

```bash
npm install
```

## Локальный запуск

```bash
npm run dev
```

Откроется адрес вида `http://localhost:5173`.

## Проверка кода

```bash
npm run lint
```

## Production-сборка

```bash
npm run build
```

Собранный сайт появится в папке `dist/`. Проверить его локально:

```bash
npm run preview
```

## Публикация на GitHub Pages

Сборка уже настроена на относительные пути (`base: './'` в
`vite.config.js`), поэтому итог из `dist/` одинаково работает и в корне
домена, и при публикации из пути репозитория
(`https://username.github.io/repo-name/`) — ничего дополнительно менять не
нужно.

Варианты публикации:

1. **Через GitHub Actions (рекомендуется).** В репозитории уже есть готовый
   workflow `.github/workflows/deploy.yml`: при пуше в `main` он собирает
   проект и публикует `dist/` в GitHub Pages. Один раз включите Pages в
   настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
2. **Вручную.** Соберите проект (`npm run build`) и залейте содержимое
   `dist/` в ветку `gh-pages` любым удобным способом (например, пакетом
   `gh-pages`) или через **Settings → Pages → Deploy from a branch**.

> Ничего не публикуется автоматически при обычной работе с кодом — деплой
> запускается только пушем в `main` (если включён workflow) или вручную.

## Где что редактировать

Весь изменяемый контент вынесен из компонентов в `src/data/`:

| Файл | Что содержит |
| --- | --- |
| `src/data/site.js` | Навигация, контакты (Instagram/E-mail), `googleFormUrl` |
| `src/data/services.js` | Список услуг (название, описание, `price` — пока `null`) |
| `src/data/cases.js` | Два кейса и их цифры |
| `src/data/portfolio.js` | Элементы галереи портфолио (тип, размер, поворот, файл) |
| `src/data/reviews.js` | Отзывы-плейсхолдеры (скриншот, цитата, имя) |
| `src/data/media.js` | Ожидаемые имена файлов для hero/about/lifestyle-фото |

Тексты внутри секций (заголовки, абзацы «Обо мне» и т. д.) — прямо в JSX
соответствующего компонента в `src/components/*/`.

### Где менять изображения

Реальных фото и видео в проекте пока нет — вместо них показывается
стилизованный `MediaPlaceholder` (зелёный editorial-плейсхолдер с подписью
ожидаемого имени файла), поэтому сайт нигде не ссылается на несуществующие
файлы.

Структура папок под будущие материалы:

```
src/assets/images/hero/        → IMG_4106.jpg (главное фото hero)
src/assets/images/about/       → IMG_8682.jpg, IMG_3056.jpg
src/assets/images/lifestyle/   → IMG_2120.jpg, IMG_2171 2.jpg
src/assets/images/portfolio/   → фото для галереи (в т.ч. IMG_4953.jpg, IMG_4021.jpg)
src/assets/reviews/            → скриншоты отзывов
```

В каждой из этих папок есть `README.md` с точной инструкцией. Общий принцип:

1. Положите файл в соответствующую папку.
2. Импортируйте его в компоненте (или в `src/data/*.js` для
   портфолио/отзывов), например:
   ```js
   import heroPhoto from '../../assets/images/hero/IMG_4106.jpg'
   ```
3. Передайте импортированную переменную в проп `src` компонента
   `MediaPlaceholder` — как только `src` задан, вместо плейсхолдера
   отрисуется реальное изображение, разметку менять не нужно.

Фото hero (`IMG_4106.jpg`) влияет на LCP — у него уже стоит проп `eager`,
чтобы оно не грузилось лениво.

### Где менять видео

Видео для портфолио (Reels/Stories) кладутся в
`src/assets/videos/portfolio/` и подключаются так же, как фото, но через
поля `src` и `poster` в `src/data/portfolio.js`. Плеер — обычный `<video
controls>` с `preload="none"`: клип не грузится, пока пользователь сам не
нажмёт play, звук никогда не включается автоматически.

### Где указать ссылку на Google Форму

Одно место: `googleFormUrl` в `src/data/site.js`. Пока значение пустое,
кнопка «Получить бесплатную консультацию» отображается как явно
неактивная (не ссылается никуда мимо) — как только вы впишете реальную
ссылку, кнопка превращается в обычную ссылку, открывающуюся в новой
вкладке.

## Архитектура

```
src/
  components/       — по одному компоненту на секцию (Header, Hero, About, ...)
  components/common/ — переиспользуемые вещи (MediaPlaceholder)
  context/          — состояние модального окна «Обсудить проект»
  data/             — весь редактируемый контент
  hooks/            — useReveal, useParallax, useCountUp, useFocusTrap и т. д.
  utils/            — scrollToId (плавный скролл к секции с учётом хедера)
```

Две отдельные CTA-логики, как и предполагает бриф:

- **«Получить бесплатную консультацию →»** — прямая ссылка на Google Форму
  (`ConsultationCTA`).
- **«Обсудить проект →»** (в хедере, hero, мобильном меню, футере) —
  открывает модальное окно выбора Instagram/E-mail (`ContactModal`),
  управляется через `ContactModalContext`.

## Доступность и производительность

- Поддержан `prefers-reduced-motion` — при включённой настройке все
  scroll-reveal, параллаксы и marquee отключаются, контент виден сразу.
- Модальное окно и мобильное меню: фокус-ловушка, закрытие по Escape/клику
  на фон, возврат фокуса на триггер после закрытия.
- Аккордеон услуг раскрывается по клику/тапу (не только по hover) — работает
  и с клавиатуры, и на touch-устройствах.
- Ни один `<img>`/`<video>` не указывает на несуществующий файл — везде,
  где реального медиа ещё нет, используется placeholder-компонент.
